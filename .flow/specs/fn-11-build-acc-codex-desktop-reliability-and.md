# ACC Codex Desktop Master Roadmap

## Goal

Build ACC as one simple product-building front door for non-technical users in Codex Desktop on Windows.

ACC coordinates work. Codex executes work. Specialist plugins provide bounded capability. Portable Markdown keeps durable memory and evidence.

## Evidence Base

Roadmap combines:

- completed ACC product foundation;
- Ruflo deep-read patterns;
- official local Codex Desktop documentation;
- real ACC session audit;
- full analyzer evidence;
- proven Codex platform limits.

## Platform Truth

ACC cannot remove Codex platform limits. ACC must not claim:

- absolute control over every plugin;
- complete hook interception;
- automatic subagent spawning without user request;
- perfect recovery from compaction;
- stable private transcript format;
- exact account-limit prediction;
- access to encrypted hidden reasoning.

ACC can still provide reliable product behavior through owned state, bounded work, verification, fallbacks, receipts, and recovery.

## Required Operating Loop

```text
User goal
-> ACC coordinator
-> canonical state transaction
-> capability selection
-> bounded specialist or Codex work
-> ACC verification
-> evidence receipt
-> state update
-> one plain result and next action
```

## Full-Behavior Rule

Every important operation uses:

```text
try -> verify -> bounded retry -> circuit breaker -> fallback -> receipt -> safe continuation
```

Core ACC behavior must not depend only on hooks, transcript parsing, native memory, subagents, automations, another plugin, or exact usage counters.

## Build Order

1. Freeze coordinator, canonical-state, evidence, and fallback contracts.
2. Enforce ACC workflow ownership and bounded specialist behavior.
3. Build one transactional canonical state and stale-verification invalidation.
4. Add active-task capsules and restart/compaction recovery.
5. Add capability registry, health probes, capacity signals, and fallbacks.
6. Add small task coordination, dependency tracking, claims, and user-approved subagents.
7. Redesign hooks as optional measured helpers with bounded repair and circuit breakers.
8. Combine evidence receipts, portable learning, security, approvals, Git, and rollback.
9. Build Doctor, recovery, installed-source checks, and plugin conflict control.
10. Add context/usage budgets and visible, stoppable background work.
11. Run installed Codex Desktop real-user QA across normal and failure paths.
12. Integrate proven foundation into original product guardrails task.

## Efficiency Rule

Use cheap checks for normal work. Use deep checks only for risky work. Reliability must reduce total rework, not add ceremony to every step.

## User Experience Rule

- Caveman communication is default everywhere user-visible when safety and clarity allow.
- User speaks naturally. Skill names are never required.
- User sees one result, important warning, and next action.
- Technical proof stays available behind simple summaries.

## Boundaries

- Windows Codex Desktop only.
- ACC remains independent; no Ruflo runtime or dependency.
- Markdown remains durable truth.
- Optional indexes and caches are rebuildable.
- No hidden learning.
- No mandatory daemon, cloud service, vector database, or federation.
- No GitHub action without explicit user command.
- Analyzer remains separate and on hold.

## Done Gate

Roadmap foundation is complete only when:

- ACC retains coordinator role or clearly reports loss of control;
- one canonical state drives every summary and resume surface;
- compaction/restart recovery restores current task and next action;
- specialist work is bounded and returns to ACC;
- hook failure does not stop core operation;
- risky actions have approval and rollback;
- every completion claim has evidence;
- Doctor detects stale state, bad install, hook failure, and plugin conflict;
- usage warnings are honest estimates, not fake exact limits;
- installed Codex Desktop tests prove natural-language setup, plan, build, correction, resume, verification, and recovery;
- non-technical user does not need plugin or skill knowledge.

## Not Part of This Planning Step

No plugin implementation, install, promotion, commit, GitHub action, release, or old analyzer dump cleanup is authorized by this roadmap record.
